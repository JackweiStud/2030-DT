# case2 Gate 2 API 契约评审

## 摘要

- 评审对象：[API-CONTRACT.md](API-CONTRACT.md) `v0.1`。
- 评审范围：case2 文件控制、结果发布、UI 数据来源、截图语义；不评审 Node/React 实现。
- 结论：`DRAFT / 不批准进入 Gate 3`。主线语义已可评审，但四项外部事实尚无证据，不能用文档猜测补齐。

## 修

| 问题 | 为什么会影响演示 | 必须修改/已固定的处理 |
|---|---|---|
| “清除 / 重置”双口径 | 前端、后端与演示人员会把同一操作理解为不同命令 | 已固定：UI 文案为“重置”，唯一协议映射为 `command=reinit`。 |
| `execute success` 被误作完成 | 会提前读取旧文件或半成品，展示假完成态 | 已固定：只有 `status=case complete` 加完整有效六文件批次才可完成。 |
| KPI 参考说明 4×5 与实物 20×1 不一致 | 前端可能把排版当接口，错误拒绝合法样本 | 已固定：每项/阶段只要求 20 个有限数值；行列分组无业务语义。 |
| 静态原型中的数字/代表热图易被沿用 | 会把 40%、50% 或代表层当成运行时结果 | 已固定：CDF、均值、降幅由当前 KPI 样本派生；正式热图运行时绘制。 |

## 跳

| 项目 | 为什么跳过 | 风险/边界 |
|---|---|---|
| REST 路由、端口、JSON response shape | 当前没有已确认的本机适配服务实现或部署事实 | Gate 3 必须在不改变本文语义的前提下补齐；本阶段不得虚构 `/api/...`。 |
| 轮询周期、超时秒数、重连退避 | 当前没有真实共享目录或运行测量 | Gate 3/5 以真实环境确定；Web 仍必须区分服务故障与业务失败。 |
| 文件锁、原子写代码、共享目录路径 | 属于实现/部署决策，尚未冻结 | 不进入 Gate 2 文档或代码；结果必须满足完整同批的语义要求。 |
| AOA/ZOA 与 `without dt` | 不驱动当前可见 UI 或演示主线 | 不得作为“未来兼容”字段混入 case2 正式结果批次。 |

## 待确认（阻塞 v1 批准）

| ID | 待确认事项 | 所需确认者 | 最小可接受证据 |
|---|---|---|---|
| P0-1 | 后端如何证明六个 Calibrated 文件同批、完整且属于本次运行 | 后端负责人 + 用户 | 一页发布顺序/批次标记规则，覆盖失败和重试。 |
| P0-2 | `reinit` 后 `command`、`status` 的最终值与时机 | 后端负责人 + 用户 | 一条可重放时序，说明刷新时如何回到 Initial。 |
| P0-3 | 适配服务的逻辑操作如何落到本机 REST、挂载路径、锁和超时 | 前端/部署负责人 + 用户 | 路由表与责任边界；不需要实现代码。 |
| P0-4 | 截图输出、成功回执、失败重试和重启去重 | 前端/部署负责人 + 用户 | 一条成功与一条失败时序，证明未落盘不会清零。 |
