# Phase 0 范围定义

## 一句话演示承诺

在内部团队演示中，case2 以 Initial DT 误差基线为起点；演示者启动 `with dt` 校准，后端先写 `execute success` 表示命令执行成功，再以 `case complete` 表示系统测试完成；只有完成且结果完整时，才用 Calibrated DT 的热力图、CDF 左移和平均误差下降证明校准有效。“重置”操作（`reinit`）同样先经过 `execute success`，再以 `reinit complete` 表示系统重置完成并恢复初始状态。

## 受众与决策

- 受众：内部团队项目演示人员与技术评审人员。
- 决策人：项目范围、业务故事、设计冻结与后续 Gate 的用户审批；具体个人姓名未提供。
- 期望反应：能在一条主线中理解“校准降低三项误差”，而非只看到两组静态图。

## 主线故事

1. 起始状态：进入 `DT Calibration`，加载 Initial DT 的 RSS 误差、有效路径数误差、首径时延误差热力图与基线统计；Calibrated 结果不预展示。
2. 触发动作：演示者点击“启动”，前端侧通过本地适配服务在共享目录中写入 `case2 / start / with dt` 控制请求。
3. 可见变化：校准中；后端写入 `execute success` 时仍不读取结果。只有 `case complete` 且完整结果发布后，显示三组 Calibrated 热力图、CDF 和均值/降幅对比。若出现 `execute fail`，前端显示执行命令失败，后端不再写 `case complete`。
4. 结束状态：Calibrated CDF 相对 Initial 左移、平均误差下降；若 `save_picture_flag` 从 `0` 变为 `1`，前端截取完成态并由适配服务保存后清回 `0`。点击“重置”（`reinit`）后，前端禁用启动并等待 `status="reinit complete"`，成功后移除 Calibrated 数据并回到 Initial DT；若出现 `execute fail`，前端显示执行命令失败，后端不再写 `reinit complete`。

## 包含

- 共享 Shell：四 Tab、1920×1080 等比缩放、单活跃 case、公共视觉 token。
- case2：三项误差的 Initial/Calibrated 热力图、CDF、均值与运行时降幅。
- 共享目录文件交互的业务边界与前端侧 Node.js 本地适配服务规划。
- case2 完成态的受控截图保存动作。

## 不做

- case1、case3、case4 的业务实现、数据契约、视觉实现或后台状态。
- 真实后端接入、真实共享目录部署、WebSocket、账户、多用户协作、配置后台。
- `without dt` 的并行测试、AOA/ZOA 的当前 UI、旧项目的 Socket/指标/业务语义复用。
- 未经证实的“实时”“真实采集”口径，以及固定 50% 改善结论。

## 真/假数据边界

| 项目 | 类型 | 当前来源 | 演示边界 | 未来真值化路径 |
|---|---|---|---|---|
| Initial DT 文件 | 参考离线数据 | 已提供 `heatmap_init_*` 文件 | 可展示基线；来源真实性未核验 | 标注生成链路、采样时间和锁证据 |
| Calibrated DT 既有文件 | 参考离线数据 | 已提供 `heatmap_cali_*` 文件 | 仅用于设计/静态验收；不代表本次执行 | 后端在 `case complete` 前完整发布当次结果 |
| 本地打桩 Calibrated | synthetic/stub 数据 | `code/back/case2` 读取 Initial 后生成改善结果，或回退 copy 参考样本 | 可用于本地联调和内部演示走通，不代表真实采集 | 接入真实后端后替换为真实发布文件并补 QA 证据 |
| 校准业务采集 | 待联调真实数据 | 后端下位业务，当前未验证 | 当前不承诺真实端到端采集 | 真实后端按契约发布结果后补来源、采样时间和锁证据 |
| 热力图、CDF、均值、降幅 | 前端派生数据 | 矩阵/KPI 文件与既有算法说明 | 公式可复现；结论依赖输入真实性 | 冻结格式、单位、数值范围与公式 |
| 截图 PNG | 前端派生交付物 | 浏览器完成态 + Node 适配服务 | 只在触发标志消费成功后落盘 | 冻结输出路径、命名、失败处理与回执 |

## 状态与权属

| 状态/数据 | 权威方 | 前端职责 |
|---|---|---|
| `case`、`command`、`dt_type` | 前端侧适配服务写入，后端读取 | 将用户动作转换为文件控制请求 |
| `status` | 后端写入 | 解释为初始、命令执行成功、命令执行失败、测试完成或重置完成；不将 `execute success` 误作业务完成 |
| Initial/Calibrated 结果文件 | 后端发布 | 只在约定状态下读取完整批次，计算并呈现对比 |
| `save_picture_flag` | 后端置 `1`，前端侧适配服务在保存成功后置 `0` | 每次消费 `0 -> 1` 保存一张递增序号截图 |
| Tab、局部加载态、图表绘制 | 前端 case2 | 不泄漏到共享 Shell 或其他 case |

## Gate 3 已固定

- 共享目录实际路径由 `DT_SHARED_DIR` 注入（旧 `CASE2_SHARED_DIR` 仅兼容既有脚本）；Node 默认监听 `127.0.0.1:3102`。
- Web 控制快照采用 1000ms 串行轮询；不引入业务超时。
- 控制写入采用适配服务内串行 + 同目录临时文件原子替换；双端并发字段保留留作真实后端/真实挂载验收。
- 初始、校准中、完成和失败视觉已冻结；适配错误、结果错误与业务失败使用不同文案。
