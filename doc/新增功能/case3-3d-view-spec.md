# Case3 独立 3D 业务视图规格

日期：2026-09-28。本文定义新增功能；实现与验收进度只记录于 `state.md`，测试证据见 `doc/case3/QA-EVIDENCE.md`。

## 1. 范围与优先级

- 对正式 `case3-v2`（DT辅助通信）增加可切换的 3D 地图，包含预置路线、编号点、已完成进度、当前 UE、BS、LOS／单反射路径。
- 复用 case3 现有 controller、完整点选择、With/Without 展示语义、控制协议、轮询、指标与截图任务。视图切换不是业务命令。
- 本增量覆盖旧 case3 规格中“3D 禁用”和 Reflection 仅限 2D 的范围限制；其余业务规则继续以 `doc/case3/` 契约为准。
- 本次不实施 case4，不改变 case1 已冻结功能，不新增仿真、射线追踪或后端数据字段。

## 2. 与 case1 完全独立

- case3 不导入 `src/cases/case1/` 中的组件、hook、配置、类型或加载器；不调用 `/api/case1/*`，不读取 `VITE_CASE1_*`。
- 3D 组件、生命周期和辅助函数归属 `src/cases/case3-v2/`；配置统一进入现有 `case3RuntimeConfig`，样式以 `.case3v2-page` 根作用域隔离。
- 可以使用项目已有 Three.js 依赖和既有项目通用基础设施；不引入 case1 业务依赖，不把 3D 业务交给 Shell。
- 3D 几何模型直接使用 `code/web/assets/case1/3D/Beijing_Geometry.glb`（与 case1 几何层同源，不另存 case3-v2 副本）；源文件由 case1 资产维护，case3 不修改该 GLB。
- Node 增加固定只读入口 `GET /api/case3/models/geometry`，由 case3 路由固定读取上述路径，返回 `model/gltf-binary`；不接收任意文件路径，不操作共享控制文件，不调用 `/api/case1/*`。
- 模型内容随 case1 几何 GLB 更新而更新；case3 与 case1 共用同一磁盘文件，部署须包含 case1 几何 GLB。

## 3. 坐标契约

依据用户提供的 Blender 检查结果和业务轴手绘图，采用以下关系：

```text
业务坐标 B = (x, y, z)
GLB/Three.js 坐标 G = (x, z, -y)
```

| 业务正方向 | 模型正方向 |
| --- | --- |
| +X，沿白色构筑物方向 | +X |
| +Y，向绿化带纵深 | -Z |
| +Z，竖直向上 | +Y |

- 按业务原点与模型原点重合、单位为米实施。原点与预置路线已做用户截图视觉核对，证据范围与尺度限制见下节；若出现整体偏移，登记并核对标定，不逐点修正数据。
- 用户确认：3D 模型坐标单位与业务提供的实时 UE 坐标单位均为米（m）。两者按 1:1 尺度使用，仅应用 `(x,y,z) → (x,z,-y)` 轴向转换；当前 3D 场景不需要类似 `VITE_CASE4_MAP_UNITS_PER_PX=0.11` 的像素比例配置。该参数用于 2D 图片像素与业务米数之间的换算，不参与 3D 投影。前提是模型按米正确导出、加载时保留原始尺度；单位一致不代表模型测量精度已核验。
- 采用 GLB 原生场景坐标，不做 case1 式包围盒居中或最长边归一化。保留 GLB 自带节点变换，不将节点局部坐标误用为场景坐标，不将节点旋转强行清零。
- 相机参数也使用上述 GLB 原生坐标，单位为米。模型根位置为零、旋转为零、缩放为一；交互通过相机和观察目标实现，不修改模型和业务坐标。
- 路线、UE、BS、R1 全部只应用一次同一转换；不使用 2D 的 origin、unitsPerPx、图片旋转或图片偏移参数。
- Z=0 映射为模型 Y=0，不自动吸附地面、屋顶、墙面，不猜测 BS 天线高度。需要改善线条重叠时，只允许明确的显示层处理，不改业务数据、反射端点或指标计算。
- 例：业务 `(10,20,1.5)` 映射到模型 `(10,1.5,-20)`。

### 3.1 当前模型标定分析与决定（2026-09-29）

- 用户提供的 Blender「视图 → 3D 游标」截图显示位置 X/Y/Z 均为 `0 m`；红白游标位于白色构筑物交汇处，与用户指定的业务原点位置吻合。游标旋转为 `0°` 只描述游标自身姿态，不作为模型轴向校准证据。
- 对 `Beijing_Geometry.glb` 的文件检查：112 个节点直接挂在场景下，没有统一父节点额外施加整体变换。截图所选 `Container1_Win4` 的 Blender 位置 `(10.35,0,1.845)` 对应 GLB 节点位置约 `(10.35,1.845,0)`，支持既有轴转换关系。节点自身的缩放、旋转应保留，不能据此误判为整体标定偏差。
- case3 模型 GET 固定读取上述 GLB；Web 加载后保留原生场景坐标，不执行 case1 的包围盒居中或最长边归一化。
- 本次核对的 `code/comdatafiles/case3/ue_comm_coordinates_base.txt` 为下列六点，按文件顺序连线。它是本地预置验证输入，不代表真实采集结果，也不将六点数量固定为业务要求。

| 点号 | 业务坐标 (m) | 用户提供的 case3 3D 截图中的相对位置 |
| --- | --- | --- |
| 1 | `(0,0,1)` | 白色构筑物交汇处上方 |
| 2 | `(0,10,1)` | 点 1 右侧 |
| 3 | `(10,10,1)` | 点 2 下方 |
| 4 | `(10,0,1)` | 点 1 下方 |
| 5 | `(10,-10,1)` | 点 4 左侧 |
| 6 | `(0,-10,1)` | 点 5 上方 |

- 在该截图视角下，业务 +Y 向右、+X 向下；这是当前相机下的投影方向，不是固定的页面方向。用户判断路径位置与方向符合预期，文件坐标与截图点号、连线关系一致。1→2→3→4 为三条矩形边，4→5→6 向左延伸后返回上方，文件不包含闭合回点 1 的线段。
- 六点业务高度均为 `1 m`，点 1 是业务原点正上方 1 m，而非 `(0,0,0)`；相邻点的业务距离均为 `10 m`。当前证据支持原点及平面方向的视觉吻合，未用已知现场距离独立核验米制尺度，也未独立核验真实高度精度，不宣称测量级标定完成。
- **决定：当前不新增 `VITE_CASE3_3D_MODEL_ORIGIN_X/Y/Z` 或 `VITE_CASE3_3D_MODEL_ROTATION_DEG`，继续统一使用 `(x,y,z) → (x,z,-y)`。** 2D 图片需要自然像素到物理坐标的标定；当前 3D 模型已有符合现行约定的空间坐标，不因配置形式需与 2D 一致而增加参数。
- 若后续更换模型或已知对应点出现整体偏移／轴向不符，再以实际对应点确认偏差后引入统一标定。尺度异常需另核对模型单位，原点与旋转参数本身不能解决缩放问题；不逐点修改业务数据补偿模型偏差。

- 用户后续确认：真实 BS／反射效果及独立 3D BS 坐标支持符合预期。此项为用户视觉确认，不替代本仓库对真实后端、挂载或采集的独立验收。

## 4. 页面与交互

- 初次进入 case3 默认 2D；原禁用的 3D 项改为可操作按钮，并提供选中语义。
- 切换仅替换地图展示；HUD、With/Without 波束展示、底部面板、全屏数据栏和顶部 Shell 继续工作。
- Start/ReInit 期间允许切换 2D/3D；不触发 init、start、reinit，不新增轮询，不丢失当前轮完整点。其他 case Tab 的忙碌锁沿用既有规则。
- 3D：左键拖动旋转，右键拖动平移，滚轮缩放。旋转保持 Y 向上，限制翻到地下；不启用自动旋转。手势需在 Shell 等比缩放后保持一致。
- 提供与 2D 相同的复位按钮（图标、位置）：仅在用户旋转/平移/缩放后显示；点击恢复本次初始化相机参数，不触发业务 ReInit，也不清除结果。
- 同次 case3 停留中分别保留 2D 与 3D 视角，切换不重置。业务 ReInit 清理业务叠加而不承担相机复位。切离 case3、刷新后视角恢复配置初值。
- 标签面向相机，锚定对应三维点；HUD 不随场景旋转。标签与 debug 面板不得阻断地图以外的业务操作。

## 5. 业务叠加与反射

- 与现有 2D 使用同一份 baseRoute、完整点列表和 currentPoint，不另设业务进度，不显示半行或未完成点。
- 预置路线按原始顺序转换后连线；编号保持原点号；完成点与路线进度保持现有颜色和语义；UE 位于当前完整点的 `ue` 坐标。
- 沿用现有清图规则：新轮首个完整点到达前、失败及 ReInit 清除动态叠加；预置底图对应的静态模型与预置路线按既有页面语义保留。
- Reflection 继续受 `CASE3_REFLECTION_ENABLE` 和 `CASE3_BS_XYZ` 控制。2D 使用 `CASE3_BS_XYZ`；3D 优先使用可选的 `VITE_CASE3_3D_BS_XYZ`，未配则回退 `CASE3_BS_XYZ`。BS 配置均为业务坐标，进模型时统一 `(x,z,-y)`，不改成 GLB 坐标录入。
- 仅当前显示侧为 With 且现有规则允许时显示当前完整点 Reflection；Without、初始空态、失败清图、ReInit 不显示。
- `los=true`：BS → UE，标注 LOS；`los=false`：BS → R1 → UE，标注 NLOS R1。不得同时虚构额外路径或从模型自动求交生成 R1。
- 当前点更新时替换路径，不积累历史。运行中可呈现沿路径移动的亮段，完成时呈现静态路径；这是视觉动画，不代表传播时延或电磁波形。
- 三维线段遵守空间深度关系；标签可置于可读层，但不以屏幕固定线代替空间连线。遮挡效果在视觉验收中检查。

- 3D BS 标识使用蓝色气泡，内部居中显示白色加粗「基站」（14px）；气泡为 52×36 逻辑像素、面向相机，尖端锚定实际 BS 坐标，替代菱形及外置 BS 文本。沿用既有 Reflection 显隐条件，不修改业务坐标或反射端点。

## 6. 独立 debug info 与 .env 工作流

配置文件为 `D:\CODE\2030-DT\code\web\.env`，新增键如下：

| 配置键 | 含义／默认 |
| --- | --- |
| `VITE_CASE3_3D_DEBUG_INFO` | `false`；接受 true/false、1/0 |
| `VITE_CASE3_3D_CAMERA_POSITION` | 相机 GLB XYZ，三项有限数；与 TARGET 成对配置 |
| `VITE_CASE3_3D_CAMERA_TARGET` | 观察目标 GLB XYZ，三项有限数 |
| `VITE_CASE3_3D_CAMERA_ZOOM` | 正有限数，默认 1 |
| `VITE_CASE3_3D_PAN_SPEED` | 正有限数，默认 1 |
| `VITE_CASE3_3D_ROTATE_SPEED` | 正有限数，默认 1 |
| `VITE_CASE3_3D_ZOOM_SPEED` | 正有限数，默认 1 |

- POSITION/TARGET 均未配置时，根据加载后模型包围盒与地图宽高比计算能容纳模型的初始斜视相机（从 +X、+Y、+Z 一侧观察，目标为包围盒中心）。不挪动、归一化模型。复位使用本次求出的初值。
- 只配置 POSITION/TARGET 中一项、三元组格式错误、位置与目标重合、非有限数或非正的 zoom/speed，应明确提示 case3 3D 配置错误；不静默使用 case1 参数。2D 与业务主线仍可用。
- 相机固定 Y 向上，采用固定透视 FOV 40°，用户不调整 roll；near/far 根据场景范围合理设置以覆盖场景。通过 POSITION + TARGET + ZOOM 完整记录旋转、平移、缩放结果。
- debug 关闭时不显示面板，但全部相机交互仍可用；debug 开启仅在 3D 视图显示 case3 自有调试面板。
- 面板实时显示相机位置、目标、zoom、交互速度以及“业务 (x,y,z) → 模型 (x,z,-y)”说明，提供只读可选中文本和“复制参数”按钮。
- 复制内容为七行完整 env 赋值：POSITION、TARGET、ZOOM、PAN_SPEED、ROTATE_SPEED、ZOOM_SPEED，以及当前 DEBUG_INFO 开关。输出无本地化千分位，精度足以在重新加载后复现视角（至少 6 位小数，避免过早截断）。
- 旋转、平移后实时更新 position/target；滚轮缩放即使改变的是相机距离而非 camera.zoom，也必须正确反映在输出 position 中。
- 用户操作流程：在 `.env` 开启 DEBUG_INFO → 重启 dev／重新构建 → 进入 case3 3D → 调整视角、缩放与平移 → 复制参数 → 手工替换 `.env` 对应键 → 重启 dev／重新构建 → 核对恢复效果。完成后可将 DEBUG_INFO 设回 false。
- 浏览器不直接写 `.env`，不新增服务端配置写入接口，不自动持久化到 localStorage。剪贴板不可用时允许选中文本手工复制并显示提示。
- 面板事件不传播给相机控制；面板有独立标记并从业务截图中过滤。复制内容不包含其他 case 配置或环境变量。
- 实现时同步 `.env.example` 的新键与说明；本次规格编写不预写未经调试的相机值到 `.env`。

## 7. 模型加载与生命周期

- 首次进入 3D 时按需加载上述共享几何 GLB，呈现加载提示。模型约 71.5 MiB、263 万三角形，以目标 PC 实测为准，不承诺未测试的帧率。
- 同次停留复用已解析模型；隐藏 3D 时停止渲染动画和交互监听响应，不新增共享文件读取；恢复时绘制最新业务快照。
- 模型加载失败、解析失败或 WebGL 不可用时显示明确错误，允许返回 2D 和显式重试，不中断业务 controller，不自动重试业务命令。
- 切离 case3 取消尚未完成的请求，忽略迟到结果，释放模型几何/材质/纹理、renderer、controls、监听器、观察器及动画帧。GPU 资源不得依赖 case1 清理。

## 8. 截图一致性

- 3D renderer 接入现有 `resetView()` / `prepareCapture()` 句柄，controller 保持唯一截图任务与有限重试逻辑。
- 截图保存当前可见 2D 或 3D 视图，保留既有整幅舞台与业务指标；不另增后端 flag。
- 3D 截图准备必须确保模型和最终业务快照已绘制，并可靠取得 WebGL 内容。实现时选定可验证的 framebuffer 保留或显式画面快照方案，不能只等待 DOM paint。
- 截图采集临界区固定当前视图和画面，避免视图切换、相机操作或模型加载完成导致 DOM 与 canvas 不一致；采集结束释放短暂锁，上传阶段不必继续锁相机。
- 模型尚未就绪／渲染失败时不得把空白 3D 图当成功；进入既有截图失败处理与有限重试，不改变业务终态。case3 调试面板不进入截图。

## 9. 验收要求

1. 独立性：case3 源码无 case1 导入、配置和 `/api/case1/*` 请求；case1 前端未挂载时 3D 仍可通过 `/api/case3/models/geometry` 正常，部署须包含 case1 几何 GLB 文件。
2. 坐标：原点与三轴方向符合用户标注；`(10,20,1.5)` 转换正确；整条预置路线与地物关系检查通过；高度零值不被自动抬升。
3. 业务：Without/With、首点等待、运行、完成、失败、ReInit 的 2D/3D 点号、进度与反射显隐一致；切换不新增控制写或轮询。
4. 交互：Chrome 1920×1080 及 Shell 缩放窗口下，旋转、平移、缩放、复位和 HUD/Dock 操作正常；全屏数据栏与 Esc 行为保持。
5. debug：默认隐藏；开启可实时复制完整 env；修改 `.env` 并重新加载后重现视角；关闭面板不影响交互；非法参数明确报错。
6. 截图：实际生成 PNG 验证模型、点线、HUD、指标齐全且无 debug；覆盖截图时视图切换、模型未就绪与渲染失败。
7. 生命周期：反复切换视图不重新下载解析；切 case 后请求/动画停止、资源释放，重新进入恢复初值；模型不可用时 2D 可继续使用。
8. 性能：记录目标 PC 首次加载、交互与截图耗时，检查重复进入退出资源是否持续增长。测试和视觉证据写入 case3 QA 文档，不宣称真实后端、真实挂载或真实采集已验收。
9. 材质与光照观感（相对 Blender「材质预览」）：
   - **问题**：同一份几何 GLB，Blender 开启材质预览时立体感、接触暗角较符合场地预期；Web Three.js 初版仅用强半球光 + 平行光、无环境贴图、未开色调映射，画面偏平、发白、墙脚发「飘」——易被误判为模型或相机 `.env` 配错。
   - **根因**：材质预览依赖内置 HDRI（IBL）；Web 侧原光照管线不同，不是 GLB 坐标或 `CAMERA_*` 配置错误。
   - **修改方式**（`MapRenderer3D.tsx`）：`RoomEnvironment` + PMREM 写入 `scene.environment`；`ACESFilmicToneMapping` + `SRGBColorSpace`；减弱半球/平行光强度，避免冲掉 IBL。背景色仍由 `VITE_CASE3_3D_BACKGROUND_COLOR` 控制，与 IBL 分离。
   - **验收**：视觉上接近材质预览的立体感与材质层次即可，**不要求**与 Blender 像素级一致；截图与交互性能仍须可接受。case1 几何/材质层共用 `ModelViewport` 已按同一管线对齐，便于同场对照，但不改变 case3 独立性验收（第 1 条）。
