## 1. 目标、已确认决定与边界

目标：用真实文件驱动的 2D 动态路径，说明 DT 对传播环境和反射辅助定位的理解；不是无线仿真或算法效果证明。

| 项目 | 已确认行为 |
|---|---|
| UE 路径端点 | 当前已展示 Pi 的 DT 实际定位坐标，使用 Node 已归一的 DT 坐标 |
| 原 UE 图标 | 保持现有逻辑，不修改为跟随 DT；当前沿 base 预期轨迹推进。允许图标与波束起点不重合，不新增第二个 UE 图标 |
| 路径关系 | 每个 Ri 是独立的一次反射：UE→Ri→BS；不是 UE→R1→R2→BS |
| LOS | losFlag=1：画 UE→BS 直达线，并画所有有效反射路径 |
| NLOS | losFlag=0：不画直达线，只画有效反射路径；n=0 时无路径 |
| 更新方式 | 实时跟随当前 Pi；新点清旧路径/旧反射点，不累积历史 |
| 反射数据可用性 | 开启时运行中三轨迹与反射按Pi收齐；未到/半行等待，无效完整行计入收齐但不画无效路径。吞吐独立；完成时不等反射 |
| 开轮清理 | Start/ReInit 前 Node 清反射文件；不存在忽略；其他清理失败沿用 DATA_CLEAR_FAILED，不写业务命令 |
| 无效反射点 | 任一 XYZ 分量为65535时跳过整个Ri及其路径，不回填；保留原编号并记录日志 |
| 全部点无效 | LOS仍画直达线；NLOS不画路径 |
| 整行65535 | LOS信息未知，清全部路径，包括直达线 |
| 完成 | 按原三轨迹与最终统计门槛完成，释放缺反射的尾部点；最终快照附带反射，最终Pi缺失则清空路径，不等补齐、不重试反射 |
| 动画/截图 | 运行中循环流动；完成后停止动画，保留清晰静态路径；截图使用最终画面 |
| 重置 | 清反射点、路径和动画状态，回到等待首点；现有UE图标仍按原主流程重置 |

不做：3D Reflection、射线追踪、电磁仿真、反射算法、历史路径回放、修改已有定位误差/CEP/控制语义。Start/ReInit继续使用dt_type=all，init为空；旧值非法。

## 3. 文件与解析合同

文件：`{DT_SHARED_DIR}/case4/ue_position_with_dt_coordinates_reflection_point.txt`。

每行对应Pi，行号从1开始，不因无效记录删除或前移。格式：`losFlag,n,x1,y1,z1,...,xn,yn,zn`。支持逗号或空白分隔，BOM、LF/CRLF及行首尾空白；逐行选择分隔符，不接受同一行混合缺列。数值词法与Case4一致，有限数、可科学计数。

- losFlag必须为整数0/1；n必须为非负整数；字段数恰好2+3n。
- `1,0`：仅直达；`0,0`：无路径；`1,2,...`：直达+两条独立反射。
- 单独的65535为整行无效，不等价于n=0。
- 任一分量为原始数值65535：跳过该Ri，其他Ri保留。精确哨兵判断先于舍入，不将65534.996误判为哨兵；反射坐标保留解析精度，UI格式化不修改数据。
- 非有限数、字段数量错误、非法flag/n等结构性错误：本行invalid，不猜测修复或画残缺路径。无效分量65535是上面的例外，允许本行部分反射点有效。
- 中间空行占据对应Pi并视为invalid，不过滤重编号；正常末尾换行不增加Pi。
- 无换行但完整合法的尾行可读；不完整尾行为pending。整行写完再append，避免合法数字前缀被误读；不通过轮询次数推测点号。
- 记录至少包含Pi、Ri（如适用）、原值和原因；重复轮询同一问题可去重，不能省略首次诊断。

## 4. Node REST 增量（工程设计）

不新增 `GET /api/case4/reflection?no=Pi`，不由Web跨请求收齐。扩展现有 `/api/case4/trajectory` 与 `/api/case4/result`，原字段和错误envelope保持兼容。

工程约定：两个GET均增加可选 `reflection=true|false` query，缺省false；Web从本轮冻结的功能配置传入同一值，Node据此决定运行中收齐策略。非法值返回400，不允许客户端以query绕过/result原有控制归属及完成校验。此参数仅选择反射能力，不是点号或完成状态。

每个原有轨迹点附加以下字段（开启时必有；关闭时可省略）：

```ts
reflection: {
  state: "ready" | "invalid" | "missing";
  los: boolean | null;
  points: Array<{ id: number; x: number; y: number; z: number }>;
}
```

父记录的Pi即反射行号；ready的points仅含有效Ri，id保留原序号。ready+空points仍可能是LOS直达；invalid/missing为los=null、points=[]。

### 运行中共同前缀

- 开启时，K=min(三轨迹各自完整前缀长度, 反射已到完整行前缀长度)，返回P1～PK，三轨迹、误差和对应反射同拍推进。base边界及轨迹原校验不变。
- 反射完整无效行（整行65535、已结束的非法行、中间空行）占据原Pi，计入前缀；部分Ri无效仍是已收齐行。不得过滤后重编号，也不得要求每个Ri有效才推进。
- 目标行未到、不完整尾行不计入前缀。例如三轨迹10行、反射9行，先返回9点；反射第10行写入65535后即返回10点，其反射为invalid。
- 多文件按现有稳定快照机制读取，反射漂移/不可读不伪造为已收齐：保留已展示点，不推进新的未收齐点。诊断区分未到与读取失败；吞吐仍独立轮询。
- 反射文件不存在时运行中反射前缀为0；不能静默切回三轨迹模式。关闭功能时完全沿用原三轨迹机制，不读取反射。
- 暂无新点时保留当前已展示Pi的匹配路径；只有推进到新Pi时替换或清空，不能画新Pi轨迹却保留旧Pi路径。

### 完成快照

- `/result`仍只以原三轨迹和最终统计为成功门槛。原门槛满足后，Node对反射做一次尽力读取并附加到最终轨迹点；不将反射纳入必需文件稳定/合法收齐检查，不因它重试或返回RESULT_NOT_READY。
- 对已有且完整的对应行保留ready/invalid；缺失、半行、不可读或反射快照漂移部分按missing处理并诊断。不得用其他Pi的数据替代。
- 原/result重试仍服务原有必需数据；只有成功候选快照才执行这一次反射读取。Web收到成功后不再单独请求反射。
- 例：三轨迹30点、反射28行，运行中最多推进到P28；原/result成功后展示全部30点，P29/P30反射missing，最终画面清路径，正常完成和截图。之后补来的反射不再消费。

### 逐点诊断日志

在共享根 `out/case4/points/trajectory.jsonl`（本地对应 `code/comdatafiles/out/case4/points/trajectory.jsonl`）的对应Pi记录内附加反射信息，不另建脱离点号的反射日志主表。记录与该次REST快照一致的reflection状态、LOS标识及有效Ri坐标，Ri保留原编号；无效记录的原值、Pi、Ri（如适用）及原因保留诊断信息。

运行中记录收齐点，完成时还必须记录最终释放的尾部点及其missing状态。例如30点轨迹/28行反射，不能只留下前28点日志。最终快照使已有点的反射信息变化时，沿用日志既有变更记录机制补记，确保同轮同Pi的最新记录能还原最终快照。日志写失败仍只告警，不阻塞REST、主流程或完成；不因增加反射字段改变既有日志清理边界。

### 开始/重置清理

保留原9个动态文件清理规则，另加入可选反射文件清理（总共9个必需目标+1个可选目标）。反射文件存在则清空，ENOENT忽略；其他失败返回DATA_CLEAR_FAILED。沿用控制队列 `guard→清理→再guard→patch`，不写Start/ReInit命令；已清空文件不回滚。不要把反射加入原9文件最终合法收齐门槛。

Web开关控制展示及运行中的收齐模式，不控制Node的开轮清理。即使关闭展示也防止下轮残留；这与“清理其他文件机制一致”的决定一致。init不额外清文件，仍负责撤权。

## 5. Web 配置、匹配和绘制

在 `code/web/.env`：

```dotenv
CASE4_REFLECTION_ENABLE=true
CASE4_BS_XYZ=(1.0,5.0,7.0)
```

以上BS值为配置格式示例，不宣称是真实标定值；部署者须填实际坐标。保持键名，使用现有Vite构建配置显式读取并只注入这两个白名单值；禁止将整个.env暴露给浏览器。复用case4RuntimeConfig单一入口。工程默认：未设置enable则false；开启时BS必须为三个有限数、非哨兵；非法配置沿用现有配置错误机制，不静默制造坐标。配置是构建时配置，改动需重启开发服务或重新构建正式包。

### 实时匹配

1. 沿用原轨迹轮询，不新增反射定时器。开启时请求四路共同前缀，关闭时请求原三轨迹模式；两路吞吐不参与收齐。
2. 每次一次性提交同一Pi的三轨迹、逐点误差、反射状态；当前Pi仍取已展示共同前缀最后一点，不按反射最大行号推进。
3. 新Pi替换旧路径及R点；ready绘制，invalid/missing清空；同Pi同内容不重启动画。
4. 无新收齐点时保持当前画面；旧轮/已完成后的live响应丢弃。切Tab、刷新、重置、失败回退时清理请求及动画。
5. 功能开关在本轮固定；配置变化按现有构建/重启机制生效，不在一轮中切换同步策略。

### 视觉

- BS标记固定，其XYZ来自CASE4_BS_XYZ配置；反射点来自实时反射文件对应Pi行，标签为 NLOS R1…Rn。UE波束端点使用同一Pi的Node归一后DT实际坐标，不移动现有UE图标，不新增UE图标。
- 复用地图投影和同一变换容器，随地图缩放/旋转/平移；2D绘制投影不改变XYZ误差算法。
- 直达线绿色；反射路径紫→青渐变，不同路径可区分。完整路径始终常亮，其上叠加一段亮色光束。
- 运行中亮段沿UE→Ri→BS（直达为UE→BS）连续移动，经过Ri继续前进，到BS后回到UE循环；所有有效路径同时播放，不逐条轮播。底线不随亮段移动而消失。
- 方案5视觉：不画彩色直线骨架。可见路径为贴附小振幅正弦波纹（端点与拐角振幅收束到0，底纹相位固定不扭动；各独立路径相位错开，避免波浪同形）。白色亮段沿同一条波纹循环，各路径同时起步。完成后移除亮段，保留静态波纹。振幅/波长为展示参数，不表示场强或时延。
- 直达绿线（UE→BS）中点旁标 LOS，沿法向偏移不压波纹；反射点标 NLOS R1…Rn。
- 新点立即换路径；波束起点如做平滑插值，只对Reflection层DT端点做，原UE图标保持现状。动画途中起点与路径几何一致；首点直接出现，不从虚构坐标飞入。
- 亮段长度、亮度、移动节奏和插值时长为展示参数，不表示真实电磁波形或传播时延。优先原生SVG+局部动画，避免引入3D引擎。
- 图层不拦截现有地图手势/业务控件；标签与重要点号尽量避让。开关关闭时不渲染BS/R点/路径、不发反射请求。
- 截图自包含：波纹/亮段/Ri/BS/标签的 fill、stroke、stroke-width、dash 写在 SVG 元素上（亮段 dash 同时写 attribute 与 style）。class CSS 不作为 PNG 唯一来源；`cloneNode(true)` 后这些属性仍在。

## 6. complete、截图与重置时序

“不等待”指完成时不等反射继续生产、不为反射增加重试；原/result必需数据的有限重试与HTTP超时机制不变。

```text
收到本轮complete
→ 停止live轨迹轮询，作废在途live响应，停止流动动画
→ 原/result流程（携带本轮reflection开关）
→ 必需数据成功后，Node尽力附加一次反射快照
→ Web提交全部最终轨迹及统计，包含运行中因缺反射而未展示的尾部点
→ 最终Pi反射ready：保留静态路径；invalid/missing：清空
→ 等待最终画面paint，再生成PNG
→ 按原机制截图/init/解除busy
```

- 不发额外单点反射请求；有无截图均使用同一最终快照并停止更新。
- /result本身失败回退按原机制，清除反射；反射缺失不导致该失败。
- 完成路径冻结为可见静态形态，不能停在opacity=0；截图沿用waitForPaint并确保SVG渐变/箭头导出正常。
- 重置清除Reflection状态和动画；Node清理失败沿用原ReInit失败行为，不伪造重置完成。

## 7. 后端及打桩发布

真实后端：按本轮三轨迹Pi顺序append反射行，允许较晚到达，但开启功能时运行中会等待对应行；每行一次写完整。没路径用合法0点行；未知数据可用整行65535占位，不能漏掉中间一行导致后续Pi错位。尽量在complete前关闭反射文件；晚于最终一次读取的数据不会再显示。观察init/新轮/其他Case后停止旧任务写入，继续遵守all控制合同。

打桩Agent：在包内新增独立反射fixture与发布逻辑，不读取或改写参考目录。反射fixture缺失可允许原主线启动，输出missing场景；提供明确的正常演示样本及专用故障测试。不要用三轨迹预检条件强制反射同长，不把反射作为complete前置门槛。

replay保持反射样本语义；random阶段可复用同一反射样本（不要求随机扰动），路径端点由本轮DT坐标决定。不得为了“看起来有反射”把n=0改成有反射。测试可注入迟到/半行/无效，不新增大量生产配置。恢复重放时对存在反射文件同步清空，避免旧行号残留；正常开轮清理由Node负责。

## 8. 最小验收矩阵

| 输入/动作 | 期望 |
|---|---|
| LOS,n=0 | 仅直达 |
| LOS,n=2 | 直达+两条独立反射，不串成多跳 |
| NLOS,n=0 / n=2 | 无路径 / 两条反射，无直达 |
| R1任一分量65535，R2有效 | 仅保留R2反射；LOS按flag决定直达；日志保留Pi/R1原值 |
| 全部Ri无效 | LOS仅直达；NLOS无路径 |
| 整行65535 | 清旧反射与直达，不保留上一帧 |
| 逗号/空白、科学计数、n不符、非法flag、半行 | 合法解析；其余按invalid/pending，不改变Pi |
| 三轨迹到P5，反射仅P4 | 运行中只返回P1～P4；P5完整到达后整组推进 |
| 反射P5无效，P6有效 | P5计入收齐但清路径；P6编号不前移 |
| 运行中反射文件缺失/不可读 | 不推进未收齐点，吞吐独立；完成阶段可正常释放最终轨迹 |
| Start/ReInit反射文件不存在 | 可正常发命令 |
| 清理权限错误 | DATA_CLEAR_FAILED，控制命令未写入 |
| complete三轨迹30行、反射28行 | 展示30点，P29/P30反射missing；最终清路径，正常完成/截图，不等待补齐 |
| complete匹配ready | 静态路径，截图含同一最终Pi，不再轮询 |
| 新点/重置/切Tab后旧响应返回 | 不恢复旧路径；请求/动画无泄漏 |
| 多条路径运行→完成 | 完整底线常亮，所有亮段沿UE到BS方向同时循环；完成移除亮段，保留静态路径 |
| 逐点JSONL | 对应Pi含反射状态/LOS/有效Ri；无效值有诊断；最终释放尾点也落日志；写失败仅告警 |

## 10. 实施期工程补齐（已回写）

以下与用户语义一致，由实现锁定：

1. **JSONL 是完整快照原子覆盖**，不是追加历史。写入串行排队。`writeIfChanged` 用点坐标+反射内容指纹判断变更，同点数反射变化也要覆盖；`/result` 成功后以 `source=result` 强制写出并封印，后续 live 不得覆盖（含在途 live）。开轮 `clear` 提升代数并解除封印。写失败只告警。
2. **运行中倒退保护**：Node 反射缺失/不可读/半行时返回更短或空前缀并 `pendingTail=true`，不 422 挡轨迹。Web `LIVE_TRAJECTORY` 若 `completeCount` 小于已展示值则保留旧快照并走原 `LIVE_HINT`。不引入跨轮反射缓存。
3. **参考文件保持原语义**，不自动补齐或循环复制。打桩默认 fixture 是明确标注的模拟夹具（`code/back/case4/fixtures/REFLECTION-FIXTURE.md`），与 `01-参考资料` 原始样本区分。
4. **无换行尾行**：仅完整合法行及单独 `65535` 可消费；截断数字、尾逗号等未换行残缺一律 pending。已换行非法记录作为 invalid 占位，不卡住收齐、不改后续 Pi。
5. **反射行多于轨迹**：只使用对应 Pi，不额外推进点。最终缺失/不可信为 `missing`，不影响原九文件成功门槛。
6. **最终读取隔离**：必需九文件与控制窗口同一轮 before/read/after；变化则重试，仍变化则 409。反射不进入该门槛：原快照成功后再尽力读一次；漂移只 warn，附带当前完整行，其余 `missing`，仍 200。缺失/半行/不可读同样不挡完成。尽力附加失败则整批 `missing`。JSONL 写入串行；`/result` 封印后在途 live 不得覆盖。控制归属、轮次与旧响应隔离沿用原 `/result` 规则。运行中 `/trajectory` 仍按反射共同前缀收齐，漂移不推进未收齐点。

Vite 仅白名单注入 `CASE4_REFLECTION_ENABLE` 与 `CASE4_BS_XYZ`。缺省或空字符串视为关闭。Web 对 `/trajectory` 与 `/result` 发送同一 `reflection=true|false`。示例 BS `(1.0,5.0,7.0)` 仅供模拟，不是真实标定。
