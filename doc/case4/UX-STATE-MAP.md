# case4 UX 状态与数据展示映射

依据三张 UX 总图及本次用户补充。PNG 是输入，最终视觉契约由用户冻结的 Pencil 设计源确定；Pencil 由 Cursor 负责。

## 三方案与指标语义

用户已确认核心故事为“通过轨迹与误差证明 DT 辅助定位更准确，同时展示吞吐率和 NLOS 情况”。商用方案对应 gaode，传统基站对应 without_dt，数字孪生辅助对应 with_dt。基准轨迹仅作参照。

- 三方案定位误差与 CEP 越小越好；同一概率下 CDF 对应误差越小越好，不按方案名称强制曲线顺序。用户进一步明确：随机模式无需每轮保持 DT / 传统基站 / 商用的最终统计优劣排序。
- 吞吐率仅对比 with_dt / without_dt，忠实展示改善或代价；当前参考样本有 DT 吞吐均值更低。
- NLOS 展示平均非视距径占比，是场景统计，不能把占比高直接标成性能更好。
- 用户明确 random 模式的 CDF/CEP 沿用参考统计小幅扰动，不由随机轨迹重算。轨迹与最终统计属于独立模拟数据，须在打桩来源说明中写清；具体展示标记方式待定，不包装成同轮轨迹的直接统计结果。

## 逐点偏差计算（用户确认）

- `ue_position_coordinates_base.txt` 为预期轨迹；三种 realtime 坐标文件为各方案定位结果。
- 首版 2D：`d = sqrt((x-x0)^2 + (y-y0)^2)`，单位米，Z 不参与。
- 后续 3D：`d = sqrt((x-x0)^2 + (y-y0)^2 + (z-z0)^2)`；本次不实现 3D。
- UX 区域仍以“定位误差回溯”识别，但数据含义是相对预期轨迹的偏差，不把预期坐标宣称为已验收的实测真值。
- 逐点偏差由坐标派生；底部 CDF/CEP 继续读取后端统计，两者不可混作同一数据源。用户已确认各坐标文件按行号对应：第 i 行与 base 第 i 行配对为 Pi；无效坐标 65535 的处理由用户列为遗留，待用户找后端确认；不预设跳点、断线或继续运行行为。

## 地图与进度展示（用户确认）

- 与当前 case3 同场地，复用 Case3 V2 的 2D 地图和坐标映射；地图资产为 `code/web/assets/case3-v2/site-2d.jpg`，投影实现为 `code/web/src/cases/case3-v2/mapProjectionV2.ts`。
- 地图预置点位高亮/移动示意、误差区点位进度示意参考 case3 展示和实现方式，数据来源为 case4，不照抄波束业务。
- 三方案同一行收齐后，共同推进地图与误差区当前点；点位总数由 case4 base 文件决定。吞吐独立时间轴保持不变。

## 实时点位收齐（用户确认）

三种定位结果按相同行号与预期轨迹配对，三种结果同一行收齐后，一起更新该点轨迹与误差；仅向前展示连续完整点位。例如三种结果分别到 P5/P3/P4，先显示到 P3，后续等待补齐。不以数据到达顺序重新编号。吞吐率独立更新，不参与轨迹点位收齐。65535 无效点处理仍为待后端确认的遗留项，不将无效值直接视为可展示的有效点。

## 最终统计收齐（用户确认）

测试完成信号到达后，三份 CDF 文件与一份 CEP/NLOS 汇总文件全部读取、校验成功，才一起显示最终统计并启用重置。在此之前不展示部分最终统计、不提前启用重置；保留已收齐轨迹和吞吐曲线。用户确认沿用 case3 思路：最终读取累计失败 10 次（含首次）后进入“结果不完整已自动回退”，尝试 init 空闲写回，适配服务正常后允许重新开始；init 失败标记适配异常。正常完成仅重置可用，结果不完整失败是独立异常出口。

刷新恢复已获用户确认：清空前端本轮展示、撤销旧轮，初始化成功后回初始并允许重新开始，不续跑旧进度。

## 已知差异与设计约束

- 用户明确首版 2D；不按图中侧视图默认态要求实现 3D。首版地图只展示预期轨迹和三种定位实时轨迹；直射/反射路径后续支持，反射点文件不参与首版三方案轨迹收齐门槛。
- 初始/运行图重复标 CEP50%，应按最终统计语义区分 CEP50% 与 CEP90%。
- 完成图仍带暂停图标和“测试中”，以用户给定按钮规则和完成文案替代。
- 20 个点是 UX 示意，参考轨迹实际有 38 点；窗口容量与溢出展示由设计确定，不能裁掉业务数据。
- 图中厘米级误差刻度与参考 CDF 的米级范围不同，坐标轴必须按正式数值口径定稿。
- 逐点回溯来自图像解释；与“底部只有吞吐实时”的文字按区域区分理解。逐点偏差来源已明确为定位坐标与预期坐标的欧氏距离；配对按各文件相同行号，不能因某方案到达更快而按到达时间配对。
- 单点浮层已由用户确认：仅测试完成后，鼠标悬停误差回溯区某个 Pi 时显示该点三种方案具体误差；测试中不启用，不要求点击触发。用户已确认首版三种方案轨迹与误差同时显示，不提供单方案隐藏开关；图例不触发单方案显隐。
- 无效数据、启动/重置失败和结果读取失败的视觉处理待契约与设计补齐；不预设复杂新页面。

## 完成态单点误差浮层（用户确认）

这是 case4 新增交互：测试完成且最终统计四文件门槛通过后，悬停误差回溯区某个已展示点位，弹出三种方案对应的逐点误差。标题按样图为“P13定位误差”等动态点号；各行对应传统基站、商用方案、DT 辅助，包含方案颜色、名称、误差数值及米单位。数值取本轮该点已计算的 XY 欧氏距离，不读取 CDF 的对应行，不使用样图固定值。样图数值显示三位小数属于视觉参考，最终精度结合设计与数值契约明确。测试中不启用该浮层，不因此暂停采集或改变轨迹。

## 吞吐率横轴补充

用户已明确横轴显示“1、2、3…样点”，按吞吐文件的采样序号排列，不换算为秒数，不绑定地图 Pi。采样约每秒一个，但该描述不构成严格时间戳或固定间隔保证。重复读取同一行不产生新样点。

## 现场环境（用户确认）

入口、弹窗交互机制、内容与界面均保持和当前 case3 一致，不增加 case4 专属页面。

## 截图需求

## CEP 增减百分比（用户暂缓）

CEP50/90 柱图上的增减百分比在后续开发阶段再考虑；当前不冻结比较基准、公式或展示方式，不使用 UX 固定百分比。三方案 CEP50/90 数值展示仍在范围内。
