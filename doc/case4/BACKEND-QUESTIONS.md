# case4 后端问题与澄清结论

本清单记录后端答复及用户后续澄清。2026-09-15 已完成四项核心问题核对；保留原问题便于追溯，以下结论用于后续契约，不代表实现或验收完成。

## 1. 单次开始时 dt_type 填什么

case4 一次开始覆盖商用方案（高德）、传统基站（无 DT）、数字孪生辅助三种定位方案。命令及状态沿用 case2/case3。

**请确认：** `case=case4, command=start` 时，`dt_type` 的准确取值是什么？`reinit` 和 `init` 时该字段分别填什么？

用户澄清：沿用 case2/case3 的精确字符串 `"with dt"`（小写，含空格），不是 `WithDT`。用户进一步确认：start、reinit 均填 `"with dt"`；init 填空字符串 `""`。

## 2. 无效坐标 65535 如何处理

接口说明将 `65535` 定义为无效坐标。三种定位坐标按行号与预期轨迹对应，第 i 行为 Pi；三方案同一行收齐后一起展示。

**请确认：** 哪些坐标分量出现 `65535` 时该点无效？无效点是否仍占用对应行号，后续点不前移？该点应跳过展示、等待有效值还是判为异常，是否影响测试继续或最终完成？

首版只计算 XY 平面偏差，请同时说明仅 Z 无效时是否影响该点有效性。

用户补充澄清：出现无效坐标 65535 时，不采用“不画”的旧处理。按分量替换：哪个分量无效，就用同一定位方案上一个点对应分量替换，其余有效分量保持原值。保留原点号，不删除或前移行号。记录日志，至少包含方案、点号、无效分量和原始值，并记录替代值便于追溯。

用户进一步确认：首点 P1 没有上一个点时，以预期轨迹 base 第 1 行的对应分量替代。连续无效时采用前一点已归一的分量值递推，避免再次传递 65535；原始输入保持不变。若预期轨迹对应分量也无效，则没有合法替代来源，应作为初始化数据异常处理，不编造坐标。

## 3. 完成时实际轨迹点数少于预期，能否正常完成

预期轨迹来自 `ue_position_coordinates_base.txt`。假设预期有 38 点，三种定位结果均只有 30 个对应点，此时后端发出 `case complete`。

**请确认：** 这种情况允许正常完成，还是应判为结果不完整？实际轨迹是否必须覆盖预期轨迹的全部点位？

此问题是轨迹点数门槛；三份 CDF 与一份 CEP/NLOS 汇总文件全部读取、校验成功才展示最终统计的规则已明确。

后端答复：参考 case3。

已核对当前 `code/server/src/cases/case3/side-files.mjs`：不要求实际点数等于 base 点数；要求至少一个完整点、相关文件收齐、无未完成尾部且读取期间控制归属稳定。case4 按此原则，不因三方案均到 P30 而 base 有 P38 就拒绝完成；三方案仍须相互收齐，最终四份统计文件也须通过已确认门槛。用户已进一步确认 case4 保持同一机制：预期 38 点、三方案均收齐 30 点时，只要存在完整点、无未完成尾部、数据合法且最终四文件统计门槛通过，就正常完成，不补造 P31～P38，不仅因少于 base 点数触发回退。最终结果未齐或读取失败仍沿用累计失败 10 次后的回退规则。

## 4. 有/无 DT 吞吐率是否需要按样点收齐

涉及文件：

- `ue_position_without_dt_thrp.txt`
- `ue_position_with_dt_thrp.txt`

吞吐率文件追加新行，横轴显示“1、2、3…样点”，与地图轨迹 Pi 独立。例如无 DT 已到第 10 个样点，有 DT 只到第 8 个样点。

**请确认：** 两个文件相同行号是否代表可直接比较的对应样本？前端应等待同序号的两个样点收齐后一起显示，还是分别显示各自已收到的样点？完成时两条序列是否允许长度不同？

后端答复：不需要收齐；有数据就更新。

落实为两条吞吐曲线分别消费各自新增行，横轴按各自样本序号，不等待另一条曲线，不因样本数不同强行补值或截短。该规则不改变三方案轨迹按行收齐的要求。
