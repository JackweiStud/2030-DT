## 2. 分层（必须守住）

```text
新 UX PNG/切图 ──► Pencil v2 ──► web-static/case3-v2 ──► React 新皮（先挂 case5）
                                      │
真实后端/打桩 ──文件──► Node /api/case3/* ──► 业务脑（不换）──► 旧皮 case3 Tab
                                                      └──► 新皮 case5 Tab
```

皮可以换绑定位置，不能换数据权威。Cost 仍读 `costPct`，BA 仍同 `no` 比 `selectedBeamId`。点位波束回溯只展示 BeamID，不展示 X/Y。

### 2.0 CostCompareCard：静态审阅 vs 正式绑定（D18，2026-08-24）

| 层 | Gate 1.5（`web-static/case3-v2`） | 正式 React（P4 case5 新皮） |
|---|---|---|
| 左/右数字 | JS 按审阅态写死 `50` / `25` / `--` | 绑 `side.costPct`；`null` → `--` |
| 左/右 fill 显隐 | 根节点 `data-state` → CSS `display` | `costPct !== null` 才显示该侧 fill |
| 梯形柱高 | 固定 PNG，不随百分比变 | **默认同静态**：固定代表态切图；若要按 `%` 缩放/多档切图/SVG，另开决策后再做 |
| 开销变化 | 写死演示值（如 `50`） | `(with - without) / without * 100`；缺一侧、`without=0` 或 `pairValid=false` → `--`；文案随符号「减少/增加」 |

不要把静态页的 `data-state` 填充逻辑「提前改成跟数值」当作前端技术验证；要验的是上表正式列。静态页保持 S0，契约写入文档为 S1。

## 2.1 导航栏：改 vs 不改

Shell 只有一份（`Shell.tsx` + `shell.css`，顶栏高目前 78px）。做不到「只给 case3 换导航、case2 保持旧顶栏」，除非拆掉 Shell 归属。

| | 改共享 Shell（选定） | 不改 |
|---|---|---|
| 是否符合「所有 Case 同一新导航」 | 符合 | 不符合；新 case3 身体配旧顶栏 |
| 改哪些文件 | `Shell.tsx`、`shell.css`、tokens、`assets/shell/`；Gate 1.5 共享顶栏一并换 | 零 |
| case2 业务页 | 不动 | 不动 |
| case2 观感 | **顶栏会变**；若栏高不再是 78px，内容区高度跟着变，要做一次 case2 视觉回归 | 顶栏完全不动 |
| 旧 case3 Tab | 开发期业务区仍是旧皮，但顶栏会先变成新的 | 整页都旧 |
| 四 Tab / 忙锁 / 现场环境 | 开发期五个 Tab（多 `DT for Comm new`）；P5 合回仍四 Tab。忙锁与现场环境行为不变 | 不变 |
| 三杠 | 装饰，不可点，不发明菜单 | 无 |
| 工期 | 小：一套顶栏资产 + 回归 case2 一眼 | 省工，但和最新要求冲突 |

**选定改。** Pencil 要把新顶栏画进共享 chrome，不要画进 case3 业务帧里当私有件。实现时单独改 Shell，和 case5 新皮可以同一阶段，但提交上尽量分开，方便看 case2 顶栏有没有撑坏。
