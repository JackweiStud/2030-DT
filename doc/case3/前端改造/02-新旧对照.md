# 新旧对照：哪些逻辑一致、哪些会变、哪些可能新增

- 日期：2026-08-18
- 方案：B + 开发期 `case5` Tab。总路线见 [00-决策与行动路线.md](00-决策与行动路线.md)。
- 本表把「接口大致不变、界面全变」落成可验收清单。
- **阻塞：** 仓库里仍只有 v1 UX（`02-ux/case3/`）。没有新 UX 源，「新 UX」列无法填实。

判定三档：

- **一致（默认冻结）**：现状契约/状态机，新 UX 未给出相反证据前，改造时不许改。
- **确定会变**：布局、控件外观、资产；方案 B 本来就要重做。
- **必须拿新 UX 核验**：可能只是换皮，也可能是新交互/新指标；没图之前不算变更单。

## 1. 一致（默认冻结，Pencil/静态页/React 都要遵守）

这些是当前主业务，用户已说明与后端交互大致仍是这一套。未看到新 UX 明文推翻前，当作 **不变**。

| 项 | 现状 | 改造约束 |
|---|---|---|
| 演示主线 | Without → With → 三 KPI 对比 | Pencil 仍要能讲这条故事，不能改成双侧同时开跑 |
| 控制协议 | 同一 `case_control.json` 五字段；`status` 只由后端写 | 静态页假交互不得假装能写 status |
| REST | 仍是 control GET/POST、init-data、side、screenshot 五个 | Gate 1.5 **仍然不接**这些接口 |
| 命令边沿 | `start\|reinit + status=""` 才是新一轮；init 只是空闲/撤权 | 不新增 cancel / 队列 / 超时自动重试 |
| 完成门槛 | success(≥3s) → complete → 最终 side 快照完整才算完成 | 新画面可以换完成样式，不能改门槛 |
| 单侧重置 | 清本侧、留对侧历史；任意重置让 BA 增量回基线 | 新 UX 若做成「一键清双侧」，这是交互变更，要单独拍板 |
| 失败重试 | Start 失败只再 Start；ReInit 失败不恢复旧结果 | 新失败样式可以换，规则不换 |
| 进页 | GET control → POST init → GET init-data；不恢复历史 | 静态页可用假 initial，正式 Web 不改握手 |
| 点位 N | 运行时动态；窗口最近 20 条不是上限 | 新 UX 若画成 P1–P12 固定格，仍按窗口而不是 12 点上限实现 |
| Cost 语义 | 单位 `%`，标题 `开销(%)`，不是 dB | 新切图若再出现 dB，实现仍用 % |
| BA 算法 | 文件基线 + 同 `no` 的 `selectedBeamId` | 环的画法可换，公式不换 |
| 开销变化 | `(with-without)/without*100` | 箭头样式可换，公式不换 |
| `pairValid` | 跨侧结论必须同代 | 新 UX 很难画出这个态；静态页至少不要把未配对画成已对比成功 |
| 截图 | Start 路径 flag 0→1，最多 3 次，ReInit 不截，落 `out/case3/` | 拍到的画面随新布局变，规则不变 |
| Shell | 1920×1080 缩放、现场环境弹窗、跨 Case 忙锁 | 成品仍四 Tab；开发期才临时多一个 case5，收工删除 |
| CSS 隔离 | `.case3-page` | 新静态页/case5 用独立根 class，不泄漏到旧 case3 |
| v1 不画 Reflection/LOS | `reflection` 仍是 With 完整点字段 | 新 UX 若画出 LOS，记入「新增」而不是默默做进换皮 |

## 2. 确定会变（方案 B 的主工作量）

用户已说明：布局、UI 元素相对当前正式 Web **整体变化**。这些不争论，直接进入新 Pencil。

| 项 | v1 现状 | 新 UX（待图） | 落点 |
|---|---|---|---|
| 设计源 | `03-design/case3/case3-dt-com.pen` | 新文件 `case3-dt-com-v2.pen`，不覆盖 v1 | Gate 1 |
| 静态验收页 | `web-static/case3/`（已 ACCEPTED，当档案） | 新建 `web-static/case3-v2/` | Gate 1.5 |
| 大布局 | 上左右双地图 / 下三 KPI | 以新 UX 为准 | Pencil + 静态页 + React |
| 视觉组件 | SidePanel、BeamScanCard、点位窗、三 KPI 卡 | 全部按新稿重画 | 同上 |
| 切图/资产 | `02-ux/case3/` → runtime assets | 新切图走 `02-ux/case3-v2/` → `04-runtime-assets/case3/` | 三轨分离仍有效 |
| 文案/色/间距/字体 | Gate 1 v1 token | 以新 Pencil 为准 | 视觉契约换代 |
| 正式 React 皮 | `Case3Page` + `case3.css` + `components/*` | P4 挂到 case5，不先拆旧 Tab；api/reducer/controller 默认不动 | Gate 1.5 接受之后 |
| E2E 选择器 | 现有 DOM | 随新 DOM 改 | React 阶段 |

## 3. 必须拿新 UX 核验（可能一致，也可能新增/变化）

没新图之前，**不要当已经变更**。Pencil 开工第一件事就是用新稿把下表逐行标成：保留 / 换皮 / 删除 / 新增。

| 核对项 | 现状 | 若新 UX 变成… | 影响 |
|---|---|---|---|
| 每侧独立 Start + Reset | 有 | 合并成一个总控、或去掉 Reset | 动 reducer 互斥矩阵，不再只是换皮 |
| With Start 在 Without 完成前禁用 | 有 | 两侧都能先点 | **契约级变更**，要先改 API-CONTRACT |
| 状态徽标 | 测试中/已完成/失败等 | 文案或位置变了 | 多半只换皮；规则仍按可见态 |
| 双侧地图 | 2D 底图 + 本地缩放旋转平移 | 真 3D / 取消地图交互 / 只留一侧 | 可能动 MapRenderer，不动 REST |
| 波束 16×16 点阵 | Without 扫描+选中，With 预测 | 改成扇区、列表、或取消 | 换组件；字段仍是 beamId |
| 点位进度 20 槽 | 最近 20 | 改窗口长度、改成时间轴、或取消 | 窗口长度可变；取消则少一块 UI，数据仍在 |
| KPI 三列都在下半 | 开销/吞吐/BA | 挪到侧栏、合并、拆页 | 换布局；绑定字段不变 |
| 开销双半环 | SVG | 柱、数字卡、新表盘 | 换皮 |
| 吞吐双曲线 | SVG | 柱/表/单侧 | 换皮；仍按 `no` 绑 throughput |
| BA 开口环 + 对/错次数 | 有 | 只留百分比、或加新统计 | 多数字要先问公式，禁止用切图 89%/18/2 |
| 现场环境 | Header 链接 → Shell 弹窗 | 取消或改入口 | 多半仍走 Shell |
| Reflection/LOS 紫弧 | v1 正式不渲染 | 新稿画出来了 | **新增可视化**；字段已在点里，不必然改后端 |
| reset / failed 是否出独立画面 | Pencil v1 有帧；Gate 1.5 当时没验 | 新稿有/无这些态 | 建议 Pencil 仍补帧；静态页范围再定 |
| 未配对 / 仅 With 历史 | 正式 Web 有，UX 图几乎没有 | 新稿仍可能没有 | 正式实现必须保留逻辑；视觉用现有徽标规则表达 |
| 新按钮/新指标/新弹层 | 无 | 例如导出、切换 3D、第四 KPI | 先停，单独讨论契约 |

## 4. 本表怎么用

P0 有新 UX 之后，用第 3 节逐行标成：保留 / 换皮 / 删除 / 新增。契约级变更先停。阶段顺序以 00 为准：对照 → Pencil → 静态页 → case5 React → 合回 case3。
