# case1 范围与输入

## 演示主线

面向现有内部演示平台，在 DT Construction 中浏览数字孪生五层架构，并进入几何层、电磁层、RF 层查看预置模型和离线指标。用户已确认无需 Start/ReInit，不启动后端现场建模。本文记录已确认需求与待决策项，不代表设计冻结、接口批准或实现验收。

## 页面与加载（用户确认）

- 进入 case1 先呈现 `01-参考资料/case1/ux/00首页/首页.png` 对应首页，再后台依次准备几何层、电磁层 GLB；用户建议采用 Three.js。
- 点击左侧几何层图片，右侧进入 `01几何层/首页-环境几何层.png` 对应详情；在几何层再次点击该图片返回首页。
- 点击左侧电磁层图片，右侧进入 `02电磁层/首页-电磁层.png` 对应详情；在电磁层再次点击该图片返回首页。
- 三个详情之间可通过左侧图片切换；保留共享 Shell。RF 详情视觉输入为 `03RF层/首页-RF层 (1).png`；用户已确认点击 RF 图片进入详情，再次点击同一图片返回首页。
- 左侧五张菱形图片：首页全部正常显示；进入几何层、电磁材质层或 RF 层详情时，当前层图片保持原色，其余四张图片变暗；返回首页恢复全部正常显示。不将具体变暗透明度视为已确认设计参数。
- 仅几何层、电磁材质层、RF 层图片可点击。详情中其余两个可点击层虽变暗，仍可用于切换；知识图谱层、数字孪生应用层始终不支持点击，不打开详情或触发业务操作。
- 数据按对应页面加载，初始化读一次离线文件，不进行业务轮询。GLB 后台预加载是用户明确的例外，不因此在首页提前读取所有 KPI/TXT。
- 工程默认：各详情首次进入读取对应 TXT，同一次 case1 停留期间缓存，切离 case1 清理，重新进入后按需重新读取；不增加实时刷新功能。
- 模型加载中、失败属于资源展示状态，不继承其他 case 的业务执行状态。浏览器通过本机 Node 文件适配服务读取业务文件，不直接访问共享目录。

## 3D 交互与配置

用户于 2026-09-21 确认：几何层、电磁材质层的 3D 模型均支持鼠标旋转、缩放、平移；初始相机位置、角度、大小、平移和旋转等参数可在 `code/web/.env` 配置。

工程整理（具体变量名与默认值在 WEB-SPEC 中确定）：

- 两层分别配置，按几何/电磁材质独立分组，避免调整一个模型影响另一个；初始设置与最近视角分别存储，具体键名在施工规格中确定。
- 区分初始视图与操作手感：初始视图覆盖相机位置、朝向/观察目标、视野或缩放，以及模型初始平移、旋转、缩放；操作参数覆盖鼠标平移、旋转、缩放的速度。用户所说“平移动大小”按初始偏移与交互速度两个维度整理。
- 相机朝向采用单一明确表达，避免同时配置互相冲突的欧拉角与观察目标；具体表示在施工规格中收敛。角度单位、坐标系和缩放含义必须写入配置注释，不猜测两个 GLB 的初始参数。
- 用户进一步确认：鼠标调整后的视角持久写入 `code/web/.env`；返回首页、切换 case、重新打开 Web 后均恢复最近保存的视角，不要求重新调整；支持 Reset 回初始设置。这替代此前仅讨论停留期间缓存的方案。
- 为保留 Reset 基准，初始设置与最近视角分开保存；鼠标操作只更新当前层最近视角，不覆盖初始设置。Reset 恢复当前层初始视角并将恢复结果持久保存，避免下次进入又恢复到 Reset 前的视角；另一层不受影响。这里的 Reset 是视角复位，不是业务 ReInit，不写共享控制文件。
- 此需求须采用运行时读写：浏览器经本机 Node 适配服务读取、保存白名单内的 case1 视角配置。不能只靠 Vite 构建时 `import.meta.env`，否则保存后重开 Web 仍可能读取旧构建值；无需为了保存视角重启或重新构建 Web。组件仍消费集中校验后的配置，不直接读取 `.env` 文件。
- 保存采用交互结束后合并写入，避免每一帧写盘；接口仅允许更新指定层的视角字段，不接受任意路径或任意环境变量。保留 `.env` 其他配置和注释，串行处理并原子替换；不向浏览器返回完整 `.env`。契约需覆盖保存与 Reset 的请求顺序，防止旧保存覆盖新复位。
- 保存结果需明确反馈，写入失败不显示“已保存”；切页前尚未完成的保存需妥善收尾，不能仅依赖关闭网页时的请求。异常退出前尚未落盘的状态不承诺恢复。切离仍释放模型/GPU/事件资源，持久保存视角不等于后台常驻渲染。
- 当前仅记录需求及必要工程边界，不提前向 `.env` 写入尚无实现消费的参数。

## RF 热力图与复用边界

- 用户指定底图：`01-参考资料/case1/ux/03RF层/元素/地图.png`；数据：`heatmap_rss.txt`；融合方式参考 case2 RSS。
- 用户指定的 `03RF层/元素/信号强度.png` 经查看实际为“强→弱”的红、橙、黄、绿色标条，并非独立的热力网格图片。
- 经查看，当前 `地图.png` 已包含彩色热力网格。用户已明确后续会用无网格底图替换；当前图仅作布局参考，不能宣称其中固定颜色由 TXT 生成。最终数据叠加与坐标标定验收依赖替换后的底图，底图未到位不阻塞其他需求梳理。
- case2 代码依据：`code/web/src/cases/case2/metrics/heatmap.ts` 与 `heatmapConfig.ts`。可参考动态矩阵校验、双线性插值、马赛克网格、透明度叠加与底图原始尺寸锚区的机制。
- 用户于 2026-09-21 对数值与颜色映射明确要求参考 case2 RSS 热力图机制。按实际代码整理为：原始数值不取负、不换算 dBm；每张矩阵独立 min/max 归一化，`t=(v-min)/(max-min)`，常数矩阵固定 `t=0.5`；双线性插值后使用蓝→青→黄→红色标，值越大越偏红，再以带透明缝隙的马赛克网格按透明度叠到底图。当前样例 55 对应低端蓝色，70 对应高端红色；这是展示映射，不据此推断后端正数的物理含义。
- 实施解释：沿用 case2 完整色标，图例同步使用相同颜色；用户先前提供的红→橙→黄→绿 `信号强度.png` 保留为布局参考，不能在蓝→青→黄→红热力图旁原样使用造成错配。设计冻结时一并核对图例与热力图。
- case2 原算法首行在上、首列在左，不转置或翻转。case1 仍需按替换后的底图核对坐标映射与锚区，不复制 case2 的固定锚区参数；用户接口截图的行/X、列/Y 描述需在标定时对应到屏幕坐标。
- RSS 误差 KPI 直接读取独立标量文件，不从热力矩阵重算。

## 数据真实性与范围

- GLB 为预置离线模型；TXT 为提供的参考样例，不表述为本轮真实采集或现场建模结果。
- 热力颜色与图表、对比百分比是前端派生展示；UX 中 0.2、0.3、上升 50% 不是业务常量。RSS 误差样例为 off=1.2、on=0.8，不能照搬 UX 上升图示。
- 首页五层说明可展示；用户明确知识图谱层、数字孪生应用层不支持点击，首版不做其独立业务详情。
- 复用 1920×1080 Shell 等比缩放与 case-local 隔离；不重写其他 case，不引入 Start/ReInit 或控制文件写入，不自动创建模拟建模后端。
- 设计输入、Pencil 设计源、静态原型与正式运行资源分轨；两个 GLB 继续保持本地忽略状态，正式资源部署位置须另行确定。
