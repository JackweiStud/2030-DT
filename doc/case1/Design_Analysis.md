# case1 设计分析

模式：标准重建；目标是现有 PC 内部演示平台的设计冻结及后续前端交接。需求权威：[PHASE0-SCOPE.md](PHASE0-SCOPE.md)；页面与数值依据：[UX-STATE-MAP.md](UX-STATE-MAP.md)。设计源 `03-design/case1/case1-dt-construction.pen` 已达 `REVIEW_READY`；**未**用户冻结，不进入 Gate 1.5 / 正式实现。

## 目标与优先级

用户先了解五层架构，再点击前三层浏览模型/指标。最高优先级是首页迅速呈现、左侧导航位置稳定和右侧局部切换；详情中模型/地图为主视觉，KPI 为对比依据。鼠标调整视角后自动保存，Reset 恢复初始基准。没有业务执行过程、实时数据流或后端建模等待。

## 源图与信息架构

输入根：`01-参考资料/case1/ux/`，四主图为 `00首页/首页.png`、`01几何层/首页-环境几何层.png`、`02电磁层/首页-电磁层.png`、`03RF层/首页-RF层 (1).png`。已查看的四图均为 3840×2160，按 2:1 对应项目 1920×1080 逻辑舞台。

层次：共享 Shell → case1 内容区 → 左侧分层导航/右侧内容 → 描述、标签、KPI、模型/地图、工具 → 装饰底板。主帧共享同一导航组件，详情仅修改选中态和右侧内容。五层堆叠图及连接线可在局部容器固定定位，不能把全页图层全部直接挂根节点。

## 布局与设计语言

保留 UX 深灰背景、灰色圆角卡片、白色标题、分层强调色、左窄右宽结构。顶部尺寸/品牌/字体优先当前 Shell。内容区横向排列，左侧固定宽、右侧填满剩余空间；右侧纵向布局，详情上部描述/KPI 横排，下部模型或地图占剩余高度。首页右侧四层说明置于上部组，应用层置于底部组。

窗口变化由 Shell 整体缩放和居中；不按窗口宽度重排 case1。KPI 内部使用标题行、绘图区、标签行，数字与单位分离；文案可在给定容器内换行，不挤出图表。主要间距/圆角/字号在 Pencil 实际读取或测量后固化为 token；当前没有精确测量值，不把目测当冻结参数。

| Reset 与保存状态 | 可编辑文字/简单图形 | 新增局部工具，不借用业务 ReInit |

## 风险与可实现性

- 两个 GLB 各约 75 MB；必须区分首页绘制、模型准备、实际渲染，不承诺预加载等于无卡顿。性能在目标 PC 测。
- Pencil 只表达代表视角；旋转/平移/缩放与持久化由正式实现验收。
- `.env` 视角保存需要 Node 运行时读写；保存失败、Reset 和切页并发必须有明确反馈，不能用页面静态图证明正确。
- RF 最终锚区和坐标需要纯底图；当前允许布局设计继续，禁止称数据叠加已验收。
- 旧图标题、RF 标签、KPI 示意值和色标与当前需求存在差异，修正清单见 UX 状态映射。

没有需要新增业务问答的阻塞项。材质图例非交互、离线按页缓存和 KPI 百分比边界按工程默认推进，均需在设计评审中可见。设计交接见 `03-design/case1/REVIEW-HANDOFF.md`、`Visual_Diff.md`、`Frontend_Spec.md`。
